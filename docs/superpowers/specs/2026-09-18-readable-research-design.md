# Readable research design

Approved in conversation: retain a paper-style research site for Wanted hackathon judges and developers, assuming no AI/statistics background. Keep the separate development site linked. Preserve every original research document and existing URL while introducing approachable explanations, figures, evidence, and original details. User authorized implementation with “진행해”.

## Experience

Warm paper background, dark ink, restrained sage accent, generous spacing, numbered research sections and figures. Inspired by Astryx's consistent spacing and live examples; retain Jekyll, no React migration. Korean first, academic terminology paired with plain explanations. A compact research navigation, desktop reading outline, mobile navigation, glossary, and source links support three reading depths.

Homepage: formal title and accessible subtitle, Korean abstract, Blender instrument illustration, linked contributions, evidence states, full original text. Other pages: a plain question, short explanation, relevant chart/diagram, nearby interpretation and limitations, unchanged detailed record. Do not imply peer review or publication.

## Figures and evidence

Use Blender for an orthographic conceptual instrument: game stage, AI suggestions, human decision, event records. Export a web image and keep the reproducible script; diagram labels are HTML, not tiny baked text. No claims that the illustration reproduces an actual game screenshot. Use accessible 2D HTML/SVG for quantitative charts with visible exact values and source links. Existing six-session aggregate is 20 rule selections (6 intervention acceptance, 8 recommendation, 6 custom); it is exploratory, instrument versions are mixed, and the later Tester 6 case remains separate. Tester 6 trajectory is observed score, not learning or causal evidence. NOT RUN is distinct from zero. No extrapolated data, no unmeasured error bars. Display actual evaluation dates and conditions. Original preregistration text is immutable.

## Preservation and maintenance

All existing Markdown articles remain byte-for-byte unchanged. Layouts add the reading layer using page URL metadata; the original rendered content remains present and accessible. Preserve original heading IDs. The snapshot script continues to generate the same public Markdown; model visual summaries must derive from public source or carry verified source assertions and a regeneration/check command. Fail visibly on incompatible data instead of silently retaining stale charts. Source details are printable; anchor navigation reveals closed details. No private raw data is republished.

## Validation

Build with Jekyll. Compare original rendered text and anchors against the baseline. Check new internal links and figure sources. Run the existing public-content checker. Verify chart-source consistency. Test real desktop and mobile browser navigation, outline links, source disclosure, keyboard operation, no-JS readability, print visibility and horizontal overflow. Avoid dependencies that are unnecessary for static research publishing.
