# 연구 개요·실험환경·쉬운 요약 검토

검토 기준: `epoko77-ai/im-not-ai`의 Codex `humanize-korean/SKILL.md`, `quick-rules.md`, 필요한 항목의 `ai-tell-taxonomy.md`. 작업 기준은 커밋 `ff6afd0`의 공개 연구 소스다. 이 문서는 검토 보고서이며 사이트와 원문을 수정하지 않았다.

이 범위에서는 번역투를 일괄 제거하는 것보다 **주장의 범위, 페이지 간 구성 정보, 수치의 분모, 측정 용어의 대응**을 먼저 정리하는 편이 독자 이해에 더 도움이 된다. 아래 주요 5건은 모두 taxonomy에 억지로 넣지 않은 별도 내용·독해 검토다. 저자 확인이 필요한 주장 조정과 의미를 유지하는 표현 설명을 구분했다. AI 작성 여부나 확률은 판단하지 않는다.

## 주요 발견 5건

### 1. 우선순위 높음 — ‘현재 로컬 NPC’가 페이지마다 달라진다

- 분류: **내부 정합성 검토, taxonomy ID 없음**. 고유명사 교정이나 자동 윤문 대상이 아니다.
- 위치·짧은 원문:
  - `statement.md:45`–`46`: “NPC `kanana` → `gemma4:12b` 교체”
  - `testbed.md:87`–`90`: “로컬 채택 구성 (개발·평가)” / NPC “`ollama:kanana1.5:8b`”
  - 제한적 대조 검색: `experiments/model-selection.md:22`는 “NPC `gemma4:12b`→`kanana1.5:8b`”, 같은 파일 `:67`은 “로컬 NPC는 `ollama:gemma4:12b`”라고 쓴다.
- 영향: 독자가 개요와 실험환경을 함께 읽으면 모델 교체 방향과 현재 구성을 확정할 수 없다. 실험이 여러 날짜에 걸쳤다는 사실로 설명될 수 있지만, 표 머리말에 해당 날짜·정책이 빠져 있다.
- 권고: 최신 로컬 구성의 기준 시점을 저자가 확인하고, 예전 채택 기록과 현재 구성을 구분한다. 모델명은 검증 없이 바꾸지 않는다. `testbed.md` 표를 현재 구성표로 유지할지 특정 평가 당시 구성표로 남길지 먼저 정한다.
- 보수적 전후 예시: “로컬 채택 구성 (개발·평가)” → “로컬 평가 당시 구성 ([확인된 날짜·정책])”. 대괄호는 검토용 자리표시자이며 실제 게시 문구가 아니다. 날짜와 정책 확인 전에는 적용하지 않는다.

### 2. 우선순위 높음 — 프로젝트 실측에서 분야 전체의 부재·최상급으로 주장이 넓어진다

- 분류: **주장·근거 검토, taxonomy ID 없음**. 단순 `D-2` 의의 과장이나 `D-4` hype 빈도 탐지로 취급하지 않는다.
- 위치·짧은 원문:
  - `statement.md:13`–`16`: “어디에나 생기고 있습니다” / “측정할 방법이 없습니다.”
  - `statement.md:24`–`25`: “가장 빠른 방법이 게임이었습니다.”
  - `statement.md:42`, `:52`: “게임은 AI를 가장 빠르게 … 검증하는 환경입니다.”
- 영향: 이 프로젝트에서 하루 단위로 모델을 검증했다는 기록은 유용하다. 하지만 그 기록만으로 기존 측정 방법이 전혀 없다거나 게임이 다른 모든 환경보다 빠르다는 결론이 따라오지는 않는다. 심사위원이 기여의 범위를 과장으로 받아들일 여지가 있다.
- 권고: 분야 전체의 부재를 주장하려면 관련 연구의 범위와 근거가 필요하다. 최상급은 비교 대상·시간 정의·비교 측정이 있는지 확인한다. 없으면 저자가 프로젝트 범위의 동기와 관측으로 문장을 좁히는 방안을 선택한다.
- **저자 판단이 필요한 예시, 의미 불변 윤문 아님**:
  - 전: “사람이 언제 AI의 제안을 믿고 언제 거부하는지를 반복 가능한 조건에서 측정할 방법이 없습니다.”
  - 후 후보: “저희는 사람이 AI의 제안을 수용하거나 거부하는 선택을 반복 가능한 조건에서 측정할 실험환경을 만들고자 했습니다.”
  - 전: “게임은 AI를 가장 빠르게, 그리고 사람을 포함해서 검증하는 환경입니다.”
  - 후 후보: “저희는 이 게임 환경에서 모델 교체를 하루 단위 실측으로 결정하고, 실제 사람의 선택도 관찰했습니다.”
- 위 후보는 부재·최상급 주장을 의도적으로 조정하므로 자동 적용할 수 없다. 여기서는 외부 관련 연구나 속도 비교를 검증하지 않았다.

### 3. 우선순위 높음 — 70%의 분모가 ‘사람’인지 ‘선택’인지 개요만으로는 분명하지 않다

- 분류: **측정 설명·독해 검토, taxonomy ID 없음**.
- 위치·짧은 원문: `statement.md:35`–`37`: “플레이 세션 6판” / “AI 계열 70% · 직접 작성 30%, N이 작은 탐색적 수치”.
- 대조 근거: `plain-summary.md:40`–`42`는 “규칙을 정한 스무 번” 중 열네 번과 여섯 번이라고 명시한다. `_data/research_figures.json:133`–`151`도 6세션, 분모 20, AI 합계 14, 직접 작성 6을 기록한다. AI 합계는 AI 개입 수락 6과 AI 추천 선택 8을 합한 값이다.
- 영향: 6판 직후 70%가 나오므로 비전문 독자가 ‘참가자의 70%’로 읽을 수 있다. `N` 역시 세션 수와 선택 수 가운데 무엇인지 드러나지 않는다. 반복 선택을 각각 독립 참가자로 해석할 위험도 있다.
- 보수적 설명 보완 예시:
  - 전: “예비 집계: AI 계열 70% · 직접 작성 30%, N이 작은 탐색적 수치”
  - 후: “예비 집계: 6판에서 규칙을 선택한 20번 중 AI 계열 14번(70%) · 직접 작성 6번(30%). 작은 표본의 탐색적 수치입니다.”
- 추가 권고: ‘AI 계열’이 두 종류의 선택을 합친 값이라는 짧은 주석이나 해당 세부 집계 링크를 연결한다. 이는 새로운 결과가 아니라 다른 공개 페이지에 이미 있는 분모를 바로 붙이는 설명 보완이다. 작은 표본과 기구 변경에 관한 유보는 유지한다.

### 4. 우선순위 중간 — 쉬운 비유에서 관찰 행동이 ‘믿음’으로 읽힌다

- 분류: **측정 개념 대응 검토, taxonomy ID 없음**. 비유 자체를 `D-14`로 삭제할 사유는 아니다.
- 위치·짧은 원문: `plain-summary.md:34`–`35`: “사람은 언제 로봇을 믿는가”.
- 대조 근거: `_includes/research/glossary.html:5`는 수용을 “선택하는 행동”으로 정의하고 “AI를 믿는 마음 자체를 측정한 것은 아닙니다”라고 분명히 구분한다. `_data/reading.yml:37` 및 `_includes/research/figures/system-loop.html:10`도 로그만으로 마음을 단정하지 않는다.
- 영향: 본편보다 쉬운 문서를 먼저 읽는 독자는 선택 비율을 신뢰 비율로 기억할 수 있다. 앞서 `plain-summary.md:18`–`19`의 한 문장 요약은 이미 수용 행동을 정확하게 표현한다.
- 권고: 연구 동기인 ‘믿음’을 남기려면 실제 측정은 카드 선택이라는 점을 인접 문장에서 명시한다. 실제 측정 질문으로 통일하려면 저자 판단으로 질문 범위를 조정한다.
- **개념 범위 조정 예시, 의미 불변 윤문 아님**:
  - 전: “사람은 언제 로봇을 믿는가”
  - 후 후보: “사람은 언제 로봇의 카드를 받아들이는가”
- 본문 전체의 블록탑·로봇·공책 비유와 대응표는 유지한다. 설명 대상에 필요한 비유를 걷어내면 비전문가용 부록의 목적이 훼손된다.

### 5. 우선순위 중간 — 요약 이후 원문에서 설명 없는 전문 용어가 한꺼번에 늘어난다

- 분류: **대상 독자 난이도 검토, taxonomy ID 없음**. 기술 용어이므로 `B-2`의 ‘설명 없는 광고성 buzzword’로 오분류하지 않는다. 고유명사·약어·내용 앵커는 보존한다.
- 위치·짧은 원문:
  - `index.md:63`–`71`: “operationalize했다”, “explanation exposure”, “event-level trace”, “deterministic domain logic”.
  - `testbed.md:75`–`80`: “비트 진행 판정”, “근거 기반 억제”, “append-only 기록”, “Harness”.
  - `testbed.md:104`–`112`: 두 층 평가의 지표가 영어 명칭만으로 나열된다.
  - `_data/reading.yml:23`: “같은 러너와 통과 기준”. ‘러너’는 쉬운 용어집에서도 설명하지 않는다.
- 영향: 새 읽기 요약과 그림에서는 쉬워졌지만, 원문으로 들어가는 순간 통계·LLM·게임 엔진의 사전 지식을 동시에 요구한다. 분야가 다른 개발자가 기여와 구현 세부사항을 구별하기 어렵다.
- 권고: 원어를 제거하거나 한글로 일괄 치환하지 말고 첫 등장에 짧은 풀이를 붙인다. 업무별 역할 표에는 해당 구성요소가 게임에서 하는 실제 행위를 쓰고 전문 이름은 병기한다. 의미가 불명확한 ‘근거 기반 억제’는 작성자 정의를 확인한 뒤 풀어쓴다.
- 보수적 전후 예시:
  - 전: “실패 → 설명 → AI 제안 → Human Approval → 규칙 수정 → 재실행을 반복 가능한 게임환경으로 operationalize했다.”
  - 후: “실패 → 설명 → AI 제안 → Human Approval → 규칙 수정 → 재실행의 과정을 반복 가능한 게임환경에서 실행·측정할 수 있도록 구현했다(operationalize).”
  - 전: “모델 교체도 같은 러너와 통과 기준으로 다시 확인했습니다.”
  - 후: “모델을 교체할 때도 같은 러너(평가 실행 도구)와 통과 기준으로 다시 확인했습니다.”
- 이 예시는 독해를 위한 설명 추가이므로 quick-rules에 없는 구간을 건드리지 말라는 자동 윤문 규칙과 구분하여 편집 제안으로만 제시한다.

## taxonomy 적용 결과와 보존 판단

- `C-8`(부정 대구 2회 이상) 후보는 `statement.md:8`–`9`의 “AI로 게임을 만든 것이 아니라”와 `:24`의 “포장이 아니라 실험기구 자체”다. 다만 인용문 형태의 프로젝트 핵심 문장이고 두 표현 사이에 실질적인 문제·시스템 설명이 있다. 연속 문장을 같은 틀로 채운 사례와 다르므로 **강한 확정 지적이나 일괄 삭제 대상으로 삼지 않는다**. 같은 포지셔닝이 `index.md:28`, `testbed.md:24`, `plain-summary.md:35`에서 되풀이되는 것은 사이트 편집상 반복 검토 대상이지만 문서별 빈도 조건을 합산해 C-8 위반으로 만들지 않는다.
- `D-14`(관통 은유)에서 블록탑·로봇·공책 반복이 기계적으로 잡힐 수 있다. 사용자가 요구한 비전문가 설명이며 문서가 명시적으로 ‘비유로 읽는 요약’이다. 장르와 내용 구조 보존을 우선하여 **교육용 비유 전체를 자동 직역하지 않는다**. ‘믿음’과 ‘선택’의 개념 대응만 별도로 검토한다.
- `B-2`는 광고성 용어 규칙이다. `LLM`, `API`, `GPU`, 모델명, `trace`, `Harness`, `operationalize` 같은 실제 기술 용어를 삭제 대상으로 세지 않았다. 원어 풀이가 필요한 것과 AI 문체 탐지는 다른 문제다.
- `C-2`/`C-9`/`C-10`을 이유로 기여 C1–C3, 평가 절차, 실제 학술 제목, 단계별 흐름도, 측정표를 산문으로 해체하지 않았다. 이 나열은 탐색과 비교에 유용하다.
- 작은 표본·미실행·인과 해석 제한은 `G-1` 완곡 남발로 약화하지 않는다. 특히 `_includes/research/home.html:21`, `:38`–`39`, `_data/reading.yml:11`, `:24`, `:37`, `:119`, `glossary.html:5`, `:10`, `:13`은 유지할 가치가 크다.
- `index.md`의 영어 Abstract 및 영어 직접 인용, 코드 블록, 모델 식별자, 수치·날짜는 한국어 문체 교정 범위에서 제외했다. 이를 번역하거나 모델명 등을 ‘현재처럼 보이게’ 고치지 않았다.
- 이 범위에서 독립적으로 확정할 만큼 강한 고우선순위 S1/S2 문체 교정 건은 선정하지 않았다. 주요 발견을 채우려고 문법상 자연스러운 표현에 ID를 붙이지 않았다.

## 검토 한계

공개 소스 간 내부 대조와 한국어 편집 검토를 수행했다. 사설 저장소·실제 실행 설정·원시 참가자 로그·외부 연구 문헌을 검증하지 않았다. 따라서 어느 로컬 모델이 최종 상태인지, 외부 분야에 동일 측정법이 존재하는지, 실제 게임이 대안보다 빠른지는 확정하지 않는다. 렌더링·배포·접근성 테스트를 새로 실행하지 않았다. 윤문본을 생성하지 않았으므로 변경률, before/after 탐지 감소율, A/B/C/D 윤문 성적은 부여하지 않는다.
